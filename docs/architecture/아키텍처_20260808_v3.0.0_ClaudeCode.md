## 3. 핵심 플로우

### 3.1 녹음 3트랙 (v3.0.0)
1. 재생 준비 시 `AudioPrepareResult.path`(실제 재생 파일 — 변형본 포함)가 `PlaybackSnapshot.activeAudioPath`에 실린다.
2. 녹음 시작: dshow 캡처(입력 게인 포함) + `alignOffsetMs`(재생 위치)·`sourceAudioPath`·`tempoScale` 스냅샷.
3. 녹음 종료: 테이크 저장 → **즉시** `ffmpeg -ss/-t`로 반주 조각(`_acc.m4a`) 컷(변형본 캐시 삭제 대비 자립화).
4. 믹스: acc+보컬을 t=0 정렬로 amix (밸런스·리버브·노이즈 체인 적용). acc 없으면 구 방식 폴백.
5. 내보내기: 보컬/반주/믹스 3파일을 사용자 폴더로 복사.

### 3.2 AI 작곡 (v3.0.0)
- **보컬곡**: ComposeJobController → SongComposeClient → 8774 `POST /api/song/generate` → 5초 폴링(`detail`·`elapsed_sec` 실표시, VRAM 순번 포함) → done 시 `/output` 다운로드 → data/compose 저장 → Composition 등록.
- **BGM**: BgmComposeClient → 8766 `POST /generate`(블로킹) → 응답 즉시 `/output` 다운로드(서버가 이전 출력을 지우므로).
- **다듬기**: 한국어 스타일 → OllamaClient(gemma4:12b) → 영어 태그 미리보기(편집 가능). 실패해도 원문 진행.
- **곡 등록**: SongLibraryService.addSong 재사용(슬롯1=생성곡). 노래방 세트 옵션: 8771 분리→슬롯2 MR→lyrics_align으로 LRC 자동 싱크.

### 3.3 AI 게이트
- `PrompterSettings.localAiEnabled/cloudAiEnabled` (기본 false).
- 게이트는 **AppController 단일 지점**에서 검사(enqueueImport aiSeparate·enqueueCompose·테이크 분리) → UI·HTTP API·MCP 모두 동일하게 차단.
- OFF 시 UI는 비활성(보이되 클릭 불가)+안내, 상태 폴링 중단.

## 4. 잡·자원 정책

- 가져오기 큐·작곡 큐 각각 동시성 1 (GPU/ffmpeg 경합 방지).
- GPU 순번은 SAW 게이트웨이의 VRAM lease가 직렬화 — 앱은 상태 문구만 전달.
- 취소 의미론: 프로세스 잡(yt-dlp/ffmpeg)=kill, 8774 잡=폴링 포기, 8766=응답 무시. UI에 "서버 작업은 계속될 수 있습니다" 명시.

## 5. 관측·상태 표시

- 30초 주기 `refreshToolAvailability`: yt-dlp·ffmpeg·8771 + (로컬AI ON 시) 8774·8766.
- Ollama는 폴링하지 않고 사용 시점 조회.
- 모든 상태 칩은 색+텍스트 병행(접근성 원칙).
