# 녹음 고정 — 상시 캡처 세션 설계 (v5.16.0)

작성 2026-09-22 · 유미(Claude Code) · 감사 3갈래 → 설계 3안 → 심사 3렌즈의 종합본

## 1. 왜 바꾸는가

사용자 요청(원문): 「녹음 고정 상태에서 스페이스로 녹음 시작하면 앞에 딜레이가 있어서 시작 시점 잡기가 어렵다. 딜레이 없애달라.」 / 「녹음 및 재생은 바로 시작하고 저장 과정에서 리드인을 넣는 방식으로 바꿔.」

v5.15.2가 없앤 것: ffmpeg 레벨 줄 버퍼링(`direct=1` 누락) 탓에 스페이스마다 돌던 4.5초 입력 점검.

**아직 남은 것**: 스페이스를 누른 뒤 ffmpeg가 dshow 그래프를 짓는 0.44~0.53초 동안은 마이크가 물리적으로 닫혀 있다. 버퍼 크기·프로브 옵션·콜드/웜 어느 것으로도 40ms 넘게 줄지 않았다(실측). 테이크마다 프로세스를 띄우는 구조에서는 이 구간의 목소리를 구할 방법이 없다.

**해법**: 녹음 고정을 켜는 순간 ffmpeg 하나를 띄워 세션 파일에 계속 받아 둔다. 스페이스는 「표시(마크)」만 찍고 곧바로 재생을 건다. 정지 때 세션 파일에서 구간을 잘라 테이크로 저장한다.

## 2. 실측 근거 (감사, RØDE NT-USB Mini, ffmpeg 8.1.1)

| 항목 | 값 |
| --- | --- |
| spawn → 파일 t=0 | 440~531ms (v5.15.2 실기 테스트 474ms) |
| `-audio_buffer_size 50` 프레임 간격 | 50.0ms, 첫 RMS − t0 = 81~100ms |
| `-flush_packets 1` + raw PCM 파일 성장 | 50ms(4800바이트)씩, 실시간 대비 0~70ms 늦음 |
| 쓰는 중인 파일을 다른 핸들로 읽기 | 가능(1.5초 조각 읽어 WAV 쓰기 12ms) |
| 벽시계↔파일시각 기준점(최소값 필터) | dshow start와 1~14ms, 파일 크기 기준점과 7~10ms 일치, 45초 드리프트 0.7ms |
| `IMFMediaEngine::Play()` → 클럭 첫 전진 | 10~23ms (N=24) |
| 'q' → 종료 | 104~140ms |

## 3. 구조

### 3.1 세션 프로세스

```
ffmpeg -hide_banner -f dshow -audio_buffer_size 50 -i audio=<장치>
       -ac 1 -ar 48000 -af <volume,>astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level:file=-:direct=1
       -nostats -flush_packets 1 -t 2700 -f s16le -y <세션폴더>/<세션id>.pcm
```

- `-progress`는 뺀다(515ms 간격이라 쓸모없다).
- raw s16le mono 48k — 헤더가 없어 바이트 오프셋 = ms × 96.
- `-t 2700`: 앱이 죽어 고아가 돼도 45분·259MB에서 스스로 끝난다. 상한에 닿아 정상 종료(코드 0)하면 고정 중일 때 세션을 다시 연다.
- 세션 폴더: `getApplicationSupportDirectory()/capture_sessions/`. **OneDrive 밖**(자라는 파일이 동기화에 걸린다)이고 **%TEMP% 밖**(이 PC는 05시 정리 크론이 %TEMP%를 쓴다).
- 고정 중에는 2채널(반주 장치)을 열지 않는다 — 보컬 1채널. 설정에 반주 장치가 있으면 한 번 안내한다.

### 3.2 시계 (CaptureClock)

- 단조 `Stopwatch` 하나(µs). 프레임 줄 도착 시각과 스페이스 마크를 같은 시계로 찍는다.
- ametadata는 프레임마다 머리줄(`frame:N pts:… pts_time:T`) + 값 줄을 낸다. 프레임 k의 끝 시각은 **다음 줄의 pts**로 확정한다(프레임 길이를 가정하지 않는다).
- `offset = (앞 줄 도착 벽시계) − (다음 줄 pts)` 의 **슬라이딩 최소값**(1초 버킷 × 10개)이 기준점 `t_ref`. 도착 지연은 늦어지는 쪽으로만 생기므로 최소값이 참값에 가장 가깝다. 전역 최소가 아니라 창인 이유는 USB 마이크 발진기와 QPC의 드리프트를 따라가기 위해서다.
- 파일시각 `F(W) = W − t_ref − gap(W)`. pts 간격이 공칭+20ms를 넘으면 드롭으로 보고 그 차이를 `gap`에 누적한다(raw PCM은 pts 없이 이어 쓰이므로).
- **마크는 벽시계(µs)로만 저장**하고, 파일시각 환산은 저장(슬라이스) 시점의 수렴된 `t_ref`로 한다. gap은 「그 마크 시각까지」만 적용한다.
- 5프레임 이상 표본이 쌓여야 `isLocked`. 잠기기 전에는 마크를 거절한다.

### 3.3 스페이스 흐름 (녹음 고정 중)

시작:

1. 세션이 live + clock locked + 입력 점검 통과가 아니면 → 스낵 「마이크를 여는 중입니다 — 잠시만요」, **재생도 시작하지 않는다**(음악만 나오고 녹음은 안 되는 조용한 실패 방지).
2. 같은 동기 스택에서: `P0 = playback.precisePosition`, `markTakeStart(wallUs, P0)`, 곡·슬롯·피치·activeAudioPath·tempo를 불변 컨텍스트로 캡처.
3. `await playback.play()`. 재생이 막히면(메시지 반환) `cancelOpenTake()`.
4. 첫 await 전에 상태(`isTakeOpen`)가 뒤집히므로 재진입·유령 녹음이 구조적으로 없다. 분기 기준은 `playing`(이벤트 지연으로 늦게 서는 값)이 아니라 동기 상태 `isTakeOpen`.

정지:

1. `markTakeEnd()`(동기) → `await playback.pause()` → 저장은 **직렬 큐**(`_armedSaveChain`)에 올리고 기다리지 않는다. 다음 스페이스를 막지 않는다.
2. `pause()`는 `state.playing` 게이트를 탄다(prompter_audio_service.dart:135). 재생 직후 상태 이벤트가 오기 전에 정지하면 무동작이 되므로, 고정 모드 정지는 게이트를 우회하는 `forcePause()`를 쓴다(시작도 `forcePlay()`).
3. `pause()` 끝에서 네이티브 `currentPosition`으로 `_clock` 앵커를 확정한다 — 화살표 seek 없이 곧바로 다음 조각을 걸 때의 P0 오차를 줄인다.

조각이 없는데 재생 중이면 그냥 pause만 한다.

### 3.4 잘라내기 (computeTakeSlice — 순수 함수)

- `leadIn = min(300, F_start)` — 스페이스 300ms 전부터 담는다(「저장 과정에서 리드인」).
- `sliceStart = F_start − leadIn`, `sliceEnd = min(F_end − 60, 파일 길이)`. 끝 60ms는 정지 키 클릭 구간이라 잘라 내고 20ms 페이드아웃.
- 시작 키 클릭 `[F_start − 40, F_start + 60]`는 5ms 램프로 뮤트. 리드인 안쪽이라 이어붙이기에서는 어차피 건너뛰는 구간이다.
- `songPositionMs = max(0, P0 − leadIn − L)`, `L = 15ms`(재생 시작 지연 실측 중앙). 이미 재생 중일 때 찍은 마크(R 키)는 L을 빼지 않는다.
- 불변식: `songPositionMs + leadInMs + L == P0` (클램프 전). 속성 테스트로 고정.
- 마크 구간 < 500ms(`kMinimumTakeDuration`)면 null → 「너무 짧아 저장하지 않았습니다」.
- 끝 바이트가 디스크에 닿을 때까지 **조건 루프**로 기다린다(10ms 간격, 500ms 상한, 넘으면 있는 데까지).
- 테이크 WAV는 `.part`로 쓰고 → 크기 검증 → rename. 실패하면 세션 파일을 지우지 않고 큰 경고(CenterAlert).
- 세션 PCM 원본은 **고정을 끌 때까지 지우지 않는다**(트림 상수가 안 맞을 때의 복구 여지).

### 3.5 교차 검증 (표시만)

조각 진행 중 프레임 줄이 올 때마다 `(precisePosition − 파일시각)` 표본을 모은다(v5.15.2의 `CaptureAnchorEstimator` 재사용, 최소값). 개루프 식(P0 − L)과 40ms 넘게 어긋나면 `timelineSuspect`로 표시하고 스낵으로 알린다. **값은 개루프 식을 쓴다**(PositionClock의 resync 잡음은 양방향이라 자동 채택은 위험).

### 3.6 감시·복구

- 멈춤 판정 = **프로세스 종료** 또는 **(RMS 공백 ≥ 600ms AND 파일 크기 2틱 연속 정체)**. OR로 묶으면 UI가 밀렸을 때 오탐한다.
- 조각 도중에 세션이 죽으면 자르지 않고: 끊긴 데까지 살려 저장 → 재생 정지 → 고정 해제 → 큰 경고.
- 사이드카 `<세션id>.json`: 장치·게인·시작 시각·열린 조각의 시작 파일ms·저장 대기 구간. 스페이스 핫패스에서는 **재생을 건 뒤** 비동기로 쓴다.
- 부팅 시 남은 세션: 사이드카에 미저장 구간이 있으면 잘라서 「복구됨」 테이크로 등록하고(열린 조각의 끝은 파일 길이), 그 뒤 세션을 지운다. 사이드카가 없으면 7일 지난 것만 지운다.
- 고아 ffmpeg를 PID로 죽이지 않는다 — 이 PC는 영상 파이프라인 ffmpeg가 상시 돈다. `-t` 자멸 + 종료 훅(1초 상한) + 부팅 복구로 막는다.

### 3.7 화면

- 조작판 고정 글자(기존 `ExcludeSemantics` Text)의 **문자열만** 바꾼다: 「● 고정 — 마이크 여는 중」 → 「● 고정 ON · 마이크 열림 · 입력 좋음/작음/없음」 → 「● 고정 — 마이크 끊김」. 노드를 새로 만들거나 지우지 않는다(2026-09-22 접근성 브리지 크래시 규칙 — `lib/widgets/center_alert.dart` 머리말).
- 상태는 버튼 `semanticsLabel`에도 덧붙인다.
- **고정 대기 중(조각 없음)에는 주기 알림을 하지 않는다.** 레벨 문구의 버킷(좋음/작음/없음)이 바뀔 때만 알린다 — 전체 화면 재빌드가 크래시 노출을 키운다.
- 고정 모드에서는 「녹음을 시작했습니다」 스낵을 띄우지 않는다. 저장 스낵: 「조각 저장 — 1:23부터 2.4초」.
- 고정 켤 때 900ms 입력 점검은 세션의 RMS 줄로 한다(별도 프로브 없음). 무음이면 CenterAlert + 고정 해제. **점검이 끝나기 전에는 스페이스를 거절**한다.
- Ctrl+R: 맨 앞에서 `_armedSaveChain`을 기다린 뒤 직전 조각을 물린다. 조각이 열려 있으면 「스페이스로 멈춘 뒤에 취소해 주세요」.
- R(고정 중): 재생을 건드리지 않고 같은 세션에 마크만 찍는다(`playbackAlreadyRunning: playing`).
- 장치·게인 변경(고정 중): 열린 조각 저장 → 세션 재기동 → 입력 점검 재실행.

- GUI 앱 실행 금지, 데스크톱 스크린샷 금지, `build_deploy.ps1` 실행 금지(실행 중인 앱을 강제 종료한다), git commit/push 금지.

- 떴다 사라지는 UI에 시맨틱스 노드를 만들지 않는다. 상시 노드는 두고 라벨만 바꾼다.

- 콘솔은 cp949 — 한글 출력은 UTF-8 파일로 쓰고 읽는다.
- 주석은 한국어로 WHY를 적는다(이 저장소 관례). 파일 첫 줄 `// file: <경로>`.
- 실기 테스트는 장치를 이름으로 고른다 — 자동 선택은 꺼진 Razer 동글(디지털 무음)을 먼저 잡는다. `RØDE`가 든 장치를 우선한다.
