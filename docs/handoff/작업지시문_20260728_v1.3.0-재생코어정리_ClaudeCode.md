# 작업지시문 — v1.3.0 재생 코어 정리 (v1.2.1 → v1.3.0)

기준 커밋: `769eaf8` (v1.2.1)
상위 문서: `작업지시문_20260728_확장로드맵_ClaudeCode.md`

## 목표

**새 기능 0건.** 이후 5개 단계(유튜브·싱크·피치·녹음·트레이닝)가 올라갈 기반을 만든다. 단, 연습 로그는 **이력이 곧 가치**이므로 적재만 이번에 시작한다.

사용자에게 보이는 변화:
1. 전체화면 진행바가 **실제로 움직인다** (이전엔 멈춰 있었음)
2. 하이라이트 줄 이동이 **속도 슬라이더를 따른다**
3. 패널과 전체화면의 하이라이트가 **어긋나지 않는다**
4. 좌측 목록에 **검색창 + 4종 필터**가 생긴다
5. 설정에 **연습 기록**(곡별 횟수·시간·최근일·주 사용 키)이 생긴다

## A. 위치 시계 — `lib/controllers/position_clock.dart` (신규)

Windows 네이티브 위치 이벤트는 약 4Hz(250ms)라 싱크에 쓸 수 없다. 보간기를 둔다.

```dart
class PositionClock {
  Duration get value;            // 보간된 현재 위치
  void anchor(Duration exact);   // seek/prepare/stop — 하드 설정
  void resync(Duration native);  // 이벤트 수신 — 250ms 초과면 스냅, 이하면 25% 블렌딩
  void setRate(double rate);     // 배속 변경 시 필수 (미호출 시 선형 드리프트)
  void start();
  void pause();
}
```

- 내부 계산: `_anchor + _elapsed() * _rate`
- **경과시간 소스를 생성자로 주입**(`Duration Function()`)해 실제 시간 없이 단위 테스트
- 구동은 `Ticker`(vsync 정렬, 창 비활성 시 자동 정지). `Timer.periodic(16ms)` 금지
- 보조 재동기화는 `AudioPlayer.getCurrentPosition()`을 **500ms 주기**로. 60Hz 폴링 금지(프레임마다 플랫폼 채널 왕복)
- 일시정지 중에는 Ticker 정지

## B. 재생 컨트롤러 — `lib/controllers/playback_controller.dart` (신규)

`lib/screens/song_list_screen.dart:54-69`의 재생 상태 12개를 인수한다.

**단일 `ChangeNotifier` 금지.** 60Hz 틱이 48개 파라미터짜리 `SongListScreenContent`를 리빌드하면 안 된다.

```dart
final ValueNotifier<PlaybackSnapshot> state;  // 곡·슬롯·재생중·준비됨·길이 — 저빈도
final ValueNotifier<Duration> position;       // ~60Hz, 진행바/시간 라벨만 구독
final ValueNotifier<int> lineIndex;           // 값 변경 시에만 통지
```

`lib/services/prompter_audio_service.dart`는 **그대로 재사용**한다(API 적절). 이관 대상: `_loadSong`, `_prepareAudioForSelection`, `_togglePlayPause`, `_stopPlayback`, `_restartPlayback`, `_onSongCompleted`, `_playNextFromQueue`, `_syncAutoScroll`. `_processingQueue` 재진입 가드는 유지.

**주의**: `prepareSelection` 완료 시점에 `clock.anchor()`를 명시 호출한다. 이벤트 스트림에 맡기면 순서가 꼬인다.

## C. 줄 인덱스 — `lib/services/lyrics_progress_service.dart` (신규)

타이머를 순수 함수로 대체해 블로커 2를 구조적으로 제거한다.

```dart
int estimatedLineIndex({
  required Duration position,
  required Duration duration,
  required int lineCount,
  required double speedLevel,
});
```

전체 스크롤 모드의 `jumpTo` 타이머는 서비스에 남기되 **매 틱 `speedLevel`을 다시 읽는다**(현재는 클로저에 값으로 캡처돼 갱신되지 않음).

## E. 스키마 강화

지금 하면 30줄, 나중이면 5배가 된다.

1. **직렬화기 통합** — `toJson() => {...toMetaJson(), 'lyricsText': lyricsText};`
   현재 `toJson`/`toMetaJson`이 병존해 새 필드를 한쪽에만 넣으면 조용히 사라진다. 앞으로 5개 단계가 필드를 계속 늘린다.
2. **`songs.json` 버전 봉투** — `{"schemaVersion": 2, "songs": [...]}`
   `load()`가 디코드 타입을 감지: `List` = v1 레거시(그대로 로드 후 v2로 저장), `Map` = v2. 빌드보다 높은 버전은 한국어 메시지와 함께 거부.
3. **백업 매니페스트 실제 검증** — `backup_service.dart:32`가 `version:1`을 쓰지만 import가 읽지 않는다. 읽고 상위 버전 거부.
4. **트림 유실 버그 수정** — `backup_service.dart:127-133`이 `BackingTrack` 재구성 시 `startMs`/`endMs`를 버린다. 백업 복원 때마다 사용자가 설정한 트림이 전부 사라진다. 3·4단계가 트랙 필드를 더 늘리므로 **패턴 자체를** 고친다.
5. `_koreanInitials`를 `lib/utils/korean_text.dart`로 추출(5단계 녹음 검색이 재사용) + **질의어도 초성 정규화**해 "봄ㄴ"도 매칭되게.
6. `lib/models/app_destination.dart`에 `label`/`icon` 부여 → `app_top_nav_bar.dart:43-64`가 하드코딩 4개 대신 `values` 순회. 2·5단계가 각각 목적지를 추가하므로 선투자.

## G. 연습 로그 적재 (9번의 수집 절반)

### 모델 — `lib/models/practice_session.dart`
```dart
class PracticeSession {
  final String id;
  final String songId;
  final String songTitle;      // 스냅샷 — 곡 개명·삭제에도 로그 보존
  final DateTime startedAt;
  final int durationMs;        // 실제 재생 시간 (일시정지 제외)
  final int pitchSemitones;    // 원곡 대비, 0 = 원키 (4단계 전까지 0 고정)
  final int? backingTrackSlot;
  final bool recorded;         // 5단계에서 연결, 현재 false
}
```

### 키 표기 — `lib/utils/key_label.dart` (순수 함수)
```dart
String formatKeyLabel(int semitones) =>
    semitones == 0 ? '원키'
    : semitones > 0 ? '$semitones키 높임'
    : '${-semitones}키 낮춤';
```
1키 = 반음 1개. 4단계 피치 UI와 8단계 통계가 **이 함수 하나만** 공유해 표기가 갈리지 않게 한다.

### 세션 경계 규칙 (순수 함수로 분리)
- 재생 시작 → 정지/곡 변경/완료 시 세션 종료
- **누적 30초 미만은 기록하지 않는다** (곡 훑어보기로 로그 오염 방지)
- 같은 곡을 **60초 이내 재생 시 직전 세션에 병합** (일시정지·되감기를 별도 연습으로 세지 않음)
- 일시정지 구간은 `durationMs`에서 제외 — `PositionClock`이 이미 pause를 알고 있어 그대로 활용

### 저장 — `lib/repository/practice_log_store.dart`
`<Documents>/data/practice_log.json`, 봉투 형식 `{"schemaVersion":1,"sessions":[...]}`로 **처음부터**(맨 배열 실수 반복 금지). 추가 전용.

`songs.json`과 분리하는 이유: 즐겨찾기 토글마다 재작성되는 핫 파일에 무한 증가 로그를 섞으면 안 되고, **곡이 삭제돼도 로그는 남아야** 한다(`songId`는 소프트 FK, 표시는 `songTitle` 스냅샷).

### UI 범위 (최소)
설정 화면에 "연습 기록" 섹션 — 곡별 **횟수·총 연습시간·최근 연습일·주 사용 키**. 숫자·시간·날짜는 `AppTypography.mono`. 본격 분석 화면은 v1.8.0.

### 백업
`practice_log.json`을 백업 zip에 포함(작은 텍스트, 가치 높음). 매니페스트 `contents`에 항목 추가.

### 수동 회귀 시나리오 (리팩터링이므로 필수)
1. 곡 선택 → 반주 슬롯 선택 → 재생/일시정지/정지/처음부터
2. **전체화면 진입 후 진행바가 실제로 움직이는지** (블로커 1)
3. 속도 슬라이더를 올리면 **하이라이트 줄 이동이 빨라지는지** (블로커 2)
4. 패널과 전체화면의 하이라이트 줄이 **같은 줄인지** (중복 제거)
5. 예약 큐 자동 진행 (곡 완료 → 다음 곡)
6. 트림 설정된 곡의 시작/끝 지점 동작
7. 좌측 목록 검색창 + 4종 필터
8. **기존 `songs.json`(v1 맨 배열) 정상 로드** 후 v2 봉투로 저장
9. 기존 백업 zip 가져오기 — **트림값 보존** (버그 수정 검증)
10. 키보드 단축키(Space/F5/Escape/화살표)
11. **연습 로그**: 30초 이상 재생 후 정지 → 설정 "연습 기록"에 반영 / 10초만 재생하면 미기록 / 같은 곡 연속 재생이 1회로 병합
