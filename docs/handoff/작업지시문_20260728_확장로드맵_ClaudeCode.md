## 1. 배경

## 3. 왜 기반 정리(v1.3.0)가 먼저인가 — 구조적 블로커 3건

### 블로커 1. 전체화면 프롬프터의 재생 위치가 멈춰 있다
`lib/navigation/prompter_navigation.dart:22-23`이 `position`/`duration`을 `MaterialPageRoute` 빌더에 **값으로 한 번만** 전달한다. 라우트는 부모 `setState`로 리빌드되지 않고, `PrompterScreen.didUpdateWidget`은 `speedLevel`만 본다. **전체화면에는 살아 있는 재생 위치가 아예 없다.** 싱크(4)·녹음(6)·피치(5)가 모두 "정확한 현재 위치"를 전제하므로 이걸 두고는 진행할 수 없다.

### 블로커 2. 하이라이트 줄 이동이 타이머 기반이고 속도를 무시한다
`lib/services/prompter_auto_scroll_service.dart:51-61`이 90ms마다 무조건 한 줄씩 넘긴다(≈11줄/초). `speedLevel`은 on/off 게이트로만 쓰인다. 게다가 같은 로직이 `lib/screens/prompter_screen.dart:170-175`에 **독립 중복 구현**돼 패널과 전체화면이 서로 어긋난다.

### 블로커 3. Windows 위치 이벤트가 초당 4회뿐
Media Foundation `TIMEUPDATE` 주기(약 250ms). 가사 싱크에는 너무 거칠고, 현재는 그 4회마다 `setState`로 전체 트리를 리빌드한다.

### 더해서 — 스키마 위험
`songs.json`은 **버전 필드 없는 맨 배열**이고, `Song`에 `toJson`/`toMetaJson` **두 직렬화기가 병존**해 새 필드를 한쪽에만 넣으면 조용히 사라진다. 앞으로 5개 단계가 스키마를 계속 늘린다. 백업 복원 시 `startMs`/`endMs`가 유실되는 기존 버그(`backup_service.dart:127-133`)도 같은 자리다.

## 6. 유튜브 저작권 방침 — 2트랙

### 트랙 A — master / 개인 사용 빌드: 기능 제한 없음
요청된 최대 기능을 모두 구현하되, 앱 내 명시 문구 2종을 **필수**로 넣는다.

1. 용도 제한: **"개인이 저작권을 소유한 링크만 사용해야 합니다."**
2. 책임 소재: **"개인적 용도의 사용에 대한 책임은 사용자 본인에게 있습니다."**

표시 위치: 유튜브 가져오기 최초 사용 시 1회 안내 대화상자(확인 필요) + 가져오기 화면 상단 상시 문구. 16px 이상, 색만으로 구분하지 않음.

### 트랙 B — 공개 배포 버전: 완성 후 재검토
v1.4 이후 기능 완성 시점에 저작권 검토를 한 번 더 수행하고 공개 버전의 기능 제한 범위를 다시 논의해 확정한다. 그때까지 공개 릴리스에서 유튜브 기능을 홍보하지 않는다.

검토 항목: 기능 제외 vs 링크 소유 확인 절차 vs 문구 유지 / 배포 채널별 약관 / 라이선스 표기.

### 설계 반영
정책이 바뀌어도 코드가 갈리지 않도록 유튜브 가져오기는 **`AppDestination.jobs` + 코디네이터 한 곳으로 격리**한다. 공개 빌드에서 빼야 하면 진입점(탭 + 설정 타일)만 제거하면 된다. 다운로드 음원의 **공유·업로드·클라우드 내보내기 경로는 처음부터 만들지 않는다.** yt-dlp·demucs는 **번들하지 않고** 사용자 환경 도구를 호출한다.

## 7. 단계별 요약

### v1.3.0 — 재생 코어 정리 (상세: 별도 지시문)
`PositionClock`(4Hz→보간), `PlaybackController`(상태 이관), `LyricsProgressService`(타이머→순수함수). 스키마 봉투화·직렬화기 통합·백업 트림버그 수정. 좌측 검색 활성화. **연습 로그 적재 시작.**

### v1.4.0 — 외부 도구 + 유튜브 가져오기
- `ExternalToolLocator` — PATH/알려진 경로 탐색, 버전 캐시, 없으면 설치 안내 + 직접 경로 지정
- `ProcessRunner` — `Process.start` 기반(버퍼링·취소불가 문제로 `Process.run` 금지), 추상 클래스로 두어 `FakeProcessRunner`로 테스트(모킹 패키지 불필요)
- 진행률 파서는 **순수 함수**. ffmpeg는 `-progress pipe:1 -nostats`로 `out_time_us=` 파싱
- `JobQueueController` — 동시 실행 1건, 취소 시 부분 파일 삭제
- 작업 디렉터리 `data/tmp/<jobId>/`에서 작업 후 성공 시에만 이동
- **반주 확보 방식 선택** `MrSourceMode`: `asIs`(MR 영상 그대로·권장) / `original`(원곡) / `reduceVocal`(ffmpeg 센터채널 제거·실험적·음질저하 명시) / `aiSeparate`(v2.0.0)
- 리스크: yt-dlp는 유튜브 변경에 취약 → 버전 표시 + stderr 원문 노출 + `yt-dlp -U` 버튼

### v1.5.0 — 가사 가져오기 + 싱크
- LRCLIB(lrclib.net, 키 불필요)에서 제목·가수·길이로 조회, 실패 시 검색 폴백 + 수동 `.lrc` 가져오기
- **LRC 사이드카** `data/lrc/<songId>.lrc` — 곡 id 기준(제목 변경 캐스케이드 회피). `Song.lrcFileName` 추가 → `toMetaJson` 반영 + 백업 포함
- 타이밍은 **곡 단위**, 슬롯별 차이는 `BackingTrack.lyricsOffsetMs`로 흡수. 계산식 `t = position − startMs + offsetMs`
- **선행 표시**: 기본 오프셋을 음수(가사 먼저)로 두고 −3~+3초 조절. 큰 −/+ 버튼 + mono 표기
- `PrompterDisplayMode.timed` 추가. 3줄 창 레이아웃 재사용(전체 모드는 단일 `Text`라 줄 스크롤 불가 — 이번 범위 밖)
- 줄 인덱스 안정성: LRC가 **자기 텍스트를 들고 있게** 해 `splitLines`(빈 줄 제거) 인덱스에 의존하지 않음
- 스트레치: whisper 자동 정렬(SVIL STT) — `LyricsTimingSource` 인터페이스 뒤에 두어 착탈 가능하게

### v1.6.0 — 키(피치) 조절
- **오프라인 사전 렌더링**: `ffmpeg -filter:a "rubberband=pitch=<ratio>"`. 실시간 아님(무대에선 키를 미리 정하는 게 안전, 엔진 교체 리스크 회피)
- 비율 계산 `2^(n/12)` — `rubberband`의 `pitch`는 반음이 아니라 **비율**
- 변형본은 `data/cache/pitch/`에 캐시(파생물 → 백업 제외, 재생성 가능, LRU 정리 + 캐시 비우기 버튼). **반주 3슬롯 제한은 유지**
- 선택값은 `PrompterSettings.pitchSemitonesBySong`에 저장(`lastSelectedTrackSlotBySong` 패턴 동일)
- UI: 슬라이더 대신 **큰 −/+ 버튼**, "현재 키: 원키 / 2키 낮춤" 텍스트 병행
- rubberband 미탑재 환경 폴백: `asetrate+aresample+atempo` (음질 저하 명시)

### v1.7.0 — 녹음 + 보관함
- `record` ^5.1 (Windows 지원, 입력장치 목록 + 진폭 스트림 제공)
- WAV/PCM16/48kHz로 캡처(크래시에도 부분 파일 유효) → 종료 시 ffmpeg로 m4a 변환
- `data/recordings/<recordingId>.m4a` — **id 기준**(곡 개명에도 유지)
- **녹음 중 자동 다음곡 진행 금지** — 완료 시 정지·저장 후 "다음 곡" 버튼 명시 제공. 세 진입점(completed/endMs/5초 타이머) 모두 가드
- 별도 `recordings.json`(봉투 형식) — 곡 삭제와 독립, 코멘트·별점·태그 보유
- 합치기(반주+보컬)는 오프라인 ffmpeg `amix`, 정렬은 녹음 시작 완료 시점의 `clock.position`을 `alignOffsetMs`로 저장
- 스피커 사용 시 마이크 유입 → "헤드폰 권장" 텍스트 안내
- 레벨 미터는 막대 + **dB 숫자 + 텍스트 상태**("입력 좋음/너무 큼/소리 없음")

### v1.8.0 — 트레이닝 센터
- **일일 루틴**: 30분/60분 프리셋 (호흡 → 워밍업(립트릴·허밍) → 스케일링 → 루틴곡 → 목표곡 → 쿨다운). 로컬 JSON 에셋 번들, 런타임 네트워크 의존 없음
- **자동 체크 시너지**: 루틴곡·목표곡 단계에 등록곡을 연결하면 연습 로그가 재생을 감지해 자동 체크. 실제로 부른 것만 인정
- **연습 통계**: 기간별 추이, 곡별 횟수·시간 랭킹, **키 변화 추이**(원키 대비 상승 = 음역 향상 지표), 연속 달성일
- `data/daily_goals.json` (봉투 형식)
- 루틴 구성은 널리 통용되는 일반적 발성 교육 구조이며 특정 유료 프로그램을 옮기지 않는다. 문구는 직접 작성

### v1.9.0 — 목록 관리 강화
정렬 축(`SongSortMode`)을 필터와 분리해 추가, 다중 선택 + 일괄 예약/삭제/즐겨찾기, 태그, 중복 탐지, **고아 파일 정리 도구**(소프트 삭제 설계상 파일이 남고 단계마다 디렉터리가 늘어 필요).

### v2.0.0 — AI 보컬 분리
demucs를 **SVIL 워크스테이션에 HTTP 서비스**로 올리고(whisper 8769 패턴 동일) 앱은 파일 POST + 폴링만. Python이 앱에서 완전히 분리된다. 앱 번들 금지.
