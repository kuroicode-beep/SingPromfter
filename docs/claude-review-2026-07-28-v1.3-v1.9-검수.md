## 발견 및 수정 — 9건

### 🔴 심각 1건

**#3. 스키마 가드 무력화 (데이터 손실 가능)**
`SongMetaStore`가 상위 버전 songs.json을 예외로 거부하도록 만들어 놨는데, 정작 `SongRepository.loadSongs`의 광범위 `catch`가 그 예외를 삼켜 빈 목록을 반환했다. 이후 아무 저장이 일어나면 **상위 버전 데이터를 빈 파일로 덮어써** 가드의 목적 자체가 깨진다.
→ 수정: 리포지토리가 `SongMetaSchemaException`을 구분 처리해 오류를 기억하고, **`saveSongs`가 저장을 차단**한다. 부팅 시 사용자에게 한국어 안내를 띄운다.

### 🟠 계획 대비 누락 3건

**#1. 목표곡 자동 체크 누락** — 문서에는 "루틴곡·목표곡 자동 체크"라고 썼는데 코드는 루틴곡만 체크했다.
→ 수정: `autoCompleteNextSongStep` — 루틴곡이 이미 완료면 목표곡을 채운다.

**#2. 연습 기록 백업 미포함** — v1.3.0 지시문에서 `practice_log.json` 백업 포함을 약속했으나 미구현이었다.
→ 수정: 내보내기에 포함, 가져오기는 **id 기준 병합**(덮어쓰면 백업 이후 기록이 사라지므로).

**#7. 봉투 스키마 테스트 누락** — 계획된 v1/v2/v99 디코드 테스트가 실제로 없었다.
→ 수정: `song_meta_envelope_test.dart` 7건 추가. #3 수정의 근거이기도 하다.

### 🟡 동작 결함 3건

**#9. 오프셋 조절이 싱크 가사 연결을 끊을 수 있음** — `_adjustLyricsOffset`이 재생 스냅샷의 오래된 곡 인스턴스를 기준으로 수정해, 방금 받은 `lrcFileName`이 빠진 채 목록에 덮어써질 수 있었다(다음 실행에서 싱크 가사 소실).
→ 수정: 목록의 최신 인스턴스를 찾아 그 위에 수정한다.

**#5. 가사 선행 기본값 미적용** — 결정 사항은 "기본 선행 + 조절"인데 기본이 0(동시)이었다.
→ 수정: 싱크 가사를 처음 받으면 오프셋이 0일 때 **1초 먼저**로 설정. 사용자가 조절한 값은 건드리지 않는다.

**#8. 테이크 재생이 끝나도 버튼이 '정지'로 남음**
→ 수정: 재생 종료 이벤트를 구독해 '듣기'로 복귀.

### 🟢 사용성 2건

**#6. 녹음 중 '다음 곡' 버튼 무반응** — 가드가 조용히 막아 이유를 알 수 없었다.
→ 수정: "녹음 중에는 다음 곡으로 넘어가지 않습니다" 안내.

**#4. 진행바 드래그 중재 없음** — 계획에 명시했던 항목. 드래그 중 60Hz 위치 갱신이 손잡이를 되돌린다.
→ 수정: 드래그 중에는 로컬 값을 표시하고, 놓는 순간에만 탐색한다.
