# 완료 보고서 — v1.6.0 키(피치) 조절

작성일: 2026-07-28
작성자: Claude Code
기준: v1.5.0(`306b836`) → `1.6.0+1`

## 구현 내용

### 접근 방식: 실시간이 아니라 오프라인 렌더링

`audioplayers`에는 피치 API가 없고, Windows의 `setPlaybackRate`는 속도만 바꾼다(음정은 부수적으로 딸려 올라감). 선택지는 둘이었다.

1. 오디오 엔진 교체(media_kit 등) → 모든 재생 경로를 건드려야 하고 위험이 큼
2. **ffmpeg로 미리 변환해 두고 그 파일을 재생** ← 채택

무대에서는 키를 미리 정해 두는 편이 안전하고, 재생 중 CPU를 쓰지 않으며, 기존 오디오 계층을 손대지 않아도 된다.

### 구현

- **`utils/pitch_math.dart`** (순수 함수)
  - `semitonesToRatio` — rubberband의 `pitch` 인자는 반음이 아니라 **주파수 비율**이라 `2^(n/12)` 변환이 필요하다
  - 캐시 파일명 생성 — 같은 입력이면 항상 같은 이름이라 캐시가 안정적이다
  - ffmpeg 인자 조립 — 프로세스를 띄우지 않아 테스트 가능
- **`services/pitch_variant_service.dart`**
  - `data/cache/pitch/`에 변환본 캐시. 파생물이라 백업에서 제외하고 언제든 다시 만들 수 있다
  - rubberband 존재 여부를 한 번만 확인하고 캐시. 없으면 `asetrate+atempo` 대체 경로(음질 저하)
  - 실패 시 반쯤 만들어진 파일을 지워 다음 시도에서 캐시로 오인되지 않게 한다
- **저장 위치**: `PrompterSettings.pitchSemitonesBySong` (`'<songId>:<slot>'` 키)
  - 재생 취향이라 `songs.json`이 아니라 설정에 둔다 → 제목을 바꿔도 유지되고, 곡 목록 파일을 더럽히지 않는다
- **반주 3슬롯 제한은 유지**. 변환본은 캐시 디렉터리에 두어 슬롯을 잡아먹지 않는다

### UI
슬라이더 대신 **큰 −/+ 버튼**(50dp)과 `원키 / 2키 낮춤 / 1키 높임` 텍스트. 0을 그냥 숫자로 두지 않고 "원키"로 표기한다. 표기는 `formatKeyLabel` 한 함수만 공유해 화면마다 달라지지 않는다.

2. 처음 쓰는 키는 변환에 몇 초 걸립니다(안내 문구가 뜹니다). 같은 키를 다시 쓰면 캐시라 즉시 재생돼요.
