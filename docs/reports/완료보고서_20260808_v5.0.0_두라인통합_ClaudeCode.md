사용자 실기 앱이 v3.0.0로 "롤백"된 현상을 보고받고 통합에 착수했다.

## 한 일

1. **즉시 복구**: 바탕화면 바로가기를 dist v4.3 빌드로 되돌림. 실데이터(songs.json 11곡, v4.x 필드) 무손상 확인.
2. **통합 브랜치**: v4.3 브랜치 기준으로 master 병합 — 충돌 13개 파일 해소, 원칙은 "양쪽 기능 전부 보존".
   - 단순 합집합: recording_take(믹스 설정+correctedFrom), take_mix(믹싱 스튜디오+듀엣), app_controller(작곡 클라이언트+STT·피치코치), recordings_panel(버튼 양쪽), content/view/nav
   - 판단이 필요했던 곳:
     - **녹음 장치 설정 필드 통일**: 브랜치 `recordingDevice` ← 채택(사용자 실데이터 보존), 내 `recordingDeviceName`은 읽기 폴백 마이그레이션만 유지
     - **설정 녹음 섹션**: 브랜치 인라인 장치 선택 → `_RecordingSection`(장치+입력 볼륨 0~200%+마이크 테스트)으로 대체(상위 호환)
     - **상단 곡 추가 버튼**: v2.10.0 "조작판으로 이동" 결정을 따름(내 라인의 onAddSong 제거)
     - **버전**: v5.0.0 (양쪽이 서로 다른 v3.x를 쓴 번호 충돌 회피). VERSION_HISTORY는 브랜치 전체 이력 유지 + v5.0.0 통합 엔트리, 내 "v3.0.0" 엔트리는 v5.0.0에 흡수
3. **site/ 랜딩**: v5.0.0 + AI 스튜디오 카드(f9) 5개 언어 추가.
