## 2. 원인 규명

### 2-1. 유튜브 가져오기 403 (이중 원인)

- **근본 원인**: yt-dlp 2026 버전대는 node만으로 부족하고 **yt-dlp-ejs**(JS 챌린지 해석기, pip 패키지)가 있어야 서명을 푼다. 이게 없어서 모든 다운로드가 403으로 실패. → `py -3.13 -m pip install -U yt-dlp yt-dlp-ejs`(0.8.0)로 해결.
- **이차 원인**: 같은 영상을 반복 시도하면 유튜브가 **영상 단위로 일시 차단**한다(다른 영상은 정상). 실패가 쌓인 원래 영상 2개가 이 상태였고, 시간이 지나면 풀린다. 진단 중 같은 영상을 반복 다운로드하면 차단을 스스로 만든다는 함정도 실측 확인.
- 진단 기법: 앱이 띄우는 yt-dlp의 stderr는 화면에 안 남아서, 래퍼 exe(-v 주입 + 로그 tee)를 만들어 `shared_preferences.json`의 `flutter.tool_path_yt-dlp`에 주입해 실제 명령·에러를 캡처했다.

### 2-2. 녹음 무음 실패 (인코딩)

- Dart `Process.run`의 기본 디코딩이 시스템 코드페이지(cp949)인데 ffmpeg는 UTF-8을 내보낸다. 장치 목록의 한글 장치명 "마이크(RØDE NT-USB Mini)"가 "留덉씠??R횠DE…"로 깨진 채 저장 → 깨진 이름으로 캡처를 열다 ffmpeg 즉사(exit -5) → 앱은 "● 녹음 중" 유령 표시 유지 → R 정지 시 0초 판정("너무 짧음")으로 조용히 삭제. 그래서 파일이 안 남았다.
- ffmpeg에도 같은 래퍼 기법을 써서 `Could not find audio only device with name [留덉씠??R횠DE NT-USB Mini)]` 로그로 확정.
