## 1. 시작점

실사용 요청 하나에서 출발했다 — 「한두 줄씩 끊어 녹음해서 자연스럽게 합치고 싶다」. 조각(펀치인) 녹음 기능을 만들고 나니, 그 조각들이 **제 자리에 안 붙는** 문제가 연달아 드러났다. 원인은 서로 다른 층에 세 개가 겹쳐 있었고, 하나를 벗겨야 다음이 보였다.

## 3. 세 겹의 원인과 해결

### (1) ffmpeg가 레벨 줄을 종료할 때까지 안 내보냈다 — v5.15.2

`ametadata=print:...:file=-`는 `direct=1`이 없으면 출력을 내부 버퍼에 쌓아 **프로세스 종료 때 한꺼번에** 내보낸다(ffmpeg 8.1.1). `-progress` 줄은 정상으로 와서 「stdout은 살아 있다」고 착각하기 쉽다.

- 입력 점검이 매번 4초 타임아웃을 다 채우고 `null`을 돌려줘 `_inputVerified`가 영영 서지 않았다 → **스페이스마다 4.5초**가 붙었다. 사용자가 말한 「언제 끝날지 모르는 공백」의 정체.
- 같은 원인으로 라이브 레벨 막대 정지, 짧은 조각의 무음 오판, 「첫 RMS 줄 = 기준점」 설계가 좌표를 조각 끝으로 저장하는 회귀까지 났다.
- 해결: `direct=1` + dshow `-audio_buffer_size 50`(기본 500ms → 끝 0~0.5초 유실 해소, `q`→종료 0.53s→0.13s) + 프레임 줄 기반 좌표 역산(`CaptureAnchorEstimator`) + 최대 레벨·길이를 종료 뒤에 읽기.
- 실측: 점검 4518ms → **1638ms**(고정 켤 때 1회만).
- 🔴 가짜 러너(테스트 더블)로는 영영 안 잡힌다 — 옵트인 실기 테스트(`test/real/`, `SP_REAL_FFMPEG=1`)로 고정했다.

### (2) 마이크를 여는 데 0.45초가 걸린다 — v5.16.0

spawn → 파일 t=0이 **440~531ms**. 버퍼 크기·프로브 옵션·콜드/웜 어느 것으로도 40ms 넘게 줄지 않았다(실측). 테이크마다 프로세스를 띄우는 구조에서는 그 구간의 목소리를 구할 방법이 없다.

구조를 바꿨다 — 사용자 표현 그대로 「녹음·재생은 바로 시작하고 저장 과정에서 리드인을 넣는 방식」:

1. 고정(Alt+R)을 켜는 순간 ffmpeg 하나로 raw PCM 세션을 연다(앱 캐시 폴더, OneDrive·%TEMP% 밖).
2. 스페이스는 벽시계 마크만 **동기로** 찍고 곧바로 재생을 건다(첫 await 전에 상태가 뒤집혀 재진입·유령 녹음이 구조적으로 사라짐).
3. 정지 때 `[마크−300ms, 끝−60ms]`를 잘라 테이크로 저장한다. 저장은 직렬 큐라 다음 스페이스를 막지 않는다.

- 시계: 프레임 줄 도착 − 다음 pts의 **슬라이딩 최소값**(도착 지연은 한 방향이라 최소값이 참값에 가깝다) + pts 구멍 보정.
- 크래시·강제 종료 복구: 배타 잠금(`.lock`)으로 소유를 판정하고, 사이드카의 생존 표시까지 살려 「복구됨」 테이크로 등록.
- 실측(RØDE): 세션 열기 **556~646ms**, 조각 길이 오차 **≤0.8ms**, 슬라이스 7~15ms, 닫기 159ms, 잔류 파일·프로세스 0.

### (3) 반주 파일 자체가 이동 후 위치를 속인다 — v5.17.0

Windows Media Foundation은 VBR MP3를 Xing TOC **근사**로 seek한다. 유튜브에서 받은 파일(`yt-dlp --audio-quality 0` = VBR V0)이 전부 해당된다.

- 실측: 보고 위치와 실제 소리가 **−116~+665ms**, seek 지점마다 값이 다름(상관 1.000). CBR은 상수(320k −12ms, 192k +39ms)라 안전.
- 조각마다 seek를 새로 하므로 **조각마다 다른 오차**가 좌표에 박힌다. 캡처를 ±15ms로 맞춰도 이어붙인 박자가 안 맞는 이유였다.
- 해결: 원본은 그대로 두고 **위치 보정본(pcm_s16le WAV)** 을 뒤에서 구워 다음 로드부터 쓴다. 첫 재생을 막지 않고, 재생 중·고정 중에는 갈아타지 않는다(멈춰 있을 때만 `adoptPlaybackCopyIfIdle`). 캐시 1.5GB 상한, 백업·폰 동기화 제외, 원본 지문(size+mtime)으로 무효화.

## 4. v5.17.0에 함께 들어간 것

- **녹음 지연 보정**(설정 > 녹음, −300~+300ms, 5ms 단위): 출력·입력 지연의 합만큼 목소리가 늦게 담히므로 좌표에서 **뺀다**. 부호는 `compensateSongPositionMs` 한 곳에만 있다. 적용값은 녹음 시작 순간에 굳고 조각에 기록돼 두 번 걸리지 않는다.
- **입력 장치 자동 선택이 실제 레벨로 고른다**: 이름 기준이면 꺼진 Razer 동글(디지털 무음, RMS −96dBFS)을 먼저 잡는다. 후보를 최대 3개까지 재서 첫 비무음을 쓰고, 고른 장치를 글자로 알린다. 명시 장치는 추가 지연 0.
- **데이터 원자 저장**(`atomic_json_file`): `.tmp`→rename + `.bak` + 읽기 거부 + rescue를 공용화해 songs.json·practice_log·compositions·daily_goals·lrc/txt에 적용. 메모장 ANSI 가사 파일 하나로 곡 목록 전체가 비어 보이던 잠복 문제도 막았다.
- **조각 잇기**: 같은 줄 중복은 `recordedAt` 최신 승, 이어붙인 결과물은 다음 재료에서 제외, 줄 경계를 플레이어 축으로 통일(`lyricsOffsetMs=1800` 곡에서 스냅이 엉뚱한 곳을 잡던 문제).
- **낡은 사본 덮어쓰기 해소**: 반주 만들기·합치기·분리가 도는 사이에 준 별점·코멘트가 되돌아가던 것을 `patch(id, (cur) => ...)`로.
- **접근성 크래시 부류 정리**: SyncLockBadge의 노드 수가 켜짐/꺼짐에 따라 바뀌던 것(녹음 배지와 같은 부류) 고정.

## 5. 크래시 원인 규명 (v5.15.1)

녹음 고정·R·스페이스를 누르면 앱이 통째로 꺼졌다. `%LOCALAPPDATA%\CrashDumps`의 덤프 10건을 엔진 PDB로 심볼화한 결과 **전부 Flutter 접근성 브리지**였다.

```
AXNodeData::HasIntAttribute            <- AXPlatformNodeWin::get_accState
std::terminate                         <- AXPlatformNodeWin::get_accRole
FlutterPlatformNodeDelegate::GetParent <- get_accParent
```

키를 누르면 Windows 입력 스택(한글 IME/TSF)이 MSAA/UIA로 화면 요소를 조회하는데, 그 요소가 곧바로 사라지면(토스트·경고·녹음 표시) 엔진이 해제된 노드를 읽다 죽는다.

**규칙으로 고정**: 떴다 사라지는 UI는 시맨틱스 노드를 만들지 않고(`ExcludeSemantics`), 상시 노드를 둔 채 **라벨만 바꾼다**. 레벨 알림은 120ms로 스로틀. 근거는 `lib/widgets/center_alert.dart` 머리말에 적어 뒀다.
