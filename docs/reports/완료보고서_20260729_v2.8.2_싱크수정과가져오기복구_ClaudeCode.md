## 1. 가사 자동 맞춤 재작성

`lib/services/lyrics_align_service.dart` 전면 재작성.

### 원인 셋

**(1) 원곡−MR 위상 반전 상쇄가 성립하지 않았다.**
demucs로 분리한 MR을 mp3로 다시 인코딩한 파일이라 두 파일이 샘플 단위로 정렬돼 있지 않다. 실측한 초당 레벨:

| 구간 | 원곡 | MR | 차이 신호 |
|---|---|---|---|
| 반주만 | −17.3dB | −17.9dB | −15.0dB |

차이 신호가 원곡과 거의 같은 크기다 — 상쇄가 전혀 일어나지 않았다는 뜻이다.

→ **포락선끼리 뺀다**(원곡dB − MRdB). 위상이 안 맞아도 성립한다. 실측에서 반주 구간 0.3dB, 노래 구간 4.4dB로 또렷하게 갈린다.

**(2) 줄 시작점이 탐색 창 경계를 그대로 답으로 냈다.**
41730ms 줄의 시작점이 37720ms로 나왔는데, 탐색 창의 하한이 37730ms였다. 측정이 아니라 아티팩트다. 노래가 이어지는 구간에서는 "이 줄이 시작되는 지점"을 소리만으로 찾을 수 없다.

→ **앞이 1.5초 조용했던 줄만** 표본으로 쓴다. 같은 시작점에 여러 줄이 붙으면 첫 줄만 센다.

**(3) 부호가 반대였다.**
곡이 LRC보다 늦은데 음수 오프셋(−4260)을 넣어 가사를 더 당겼다. 총 오차 5~6초.

### 문턱 계산도 고쳤다

하위 15% ~ 상위 85% 중간값을 쓰고 있었는데, **노래가 전체의 15%도 안 되는 곡에서 무너진다** — 바닥과 봉우리가 같아져 문턱이 0이 되고 모든 프레임이 "보컬 있음"이 된다. 하위 20% ~ 상위 2%로 바꾸고 최소 이득 1.5dB를 뒀다.

### 못 맞추면 못 맞춘다고 말한다

「넌 언제나」를 다시 재니 어긋남이 이렇게 나왔다:

| 위치 | 어긋남 |
|---|---|
| 8.9초 | +640ms |
| 41.7초 | +2070ms |
| 126초 | +2650ms |
| 152초 | +3740ms |

약 1.7% **드리프트** — 곡과 속도가 다른 LRC 판본이라 오프셋 하나로는 맞출 수 없다. 표본이 1.5초 넘게 흩어지면 값을 내지 않고 이유를 설명하도록 했다.

읽는 시간 보정(`readingLeadMs`)은 제거했다 — "가사에 딱 맞춰서" 요청대로.

**현재 상태**: 해당 곡은 `lyricsOffsetMs = +1800`을 넣어 뒀다. 44초 지점에서 화면으로 확인했고 중간은 맞지만 앞뒤가 어긋난다. 제대로 하려면 `.lrc`를 다시 타이밍해야 한다.

## 2. 전체화면 조작판 상태 고정 해제

`PrompterScreen`은 `Navigator.push`의 builder로 만들어지고 **그 builder는 한 번만 돈다.** `controlsDrawerOpen`을 `widget`에서 읽고 있어 무대에 들어온 순간의 값에 얼어붙었다 — 손잡이를 눌러도 설정만 바뀌고 화면은 꿈쩍하지 않았다. 들어올 때 열려 있었으면 계속 열린 채로 남는다.

`_displayMode`·`_fontSizeLevel`과 같은 방식으로 로컬 소유로 바꾸고 위로 알리게 했다.

## 3. 한글 경로에서 유튜브 가져오기 실패

증상: 데이터 폴더가 `C:\Users\...\OneDrive\문서\data`일 때 가져오기가 **항상** 실패.

```
ERROR: Unable to download video: [Errno 22] Invalid argument
```

### 진단 과정

앱 밖에서 같은 명령을 돌리면 전부 성공했다. 차이를 하나씩 맞춰 봤지만 전부 통과:

| 시험 | 결과 |
|---|---|
| 앱과 동일한 인자 조합 | 성공 |
| OneDrive 한글 경로에 저장 | 성공 |
| `--ffmpeg-location` WinGet shim 경로 | 성공 |
| 작업 디렉터리를 한글 임시 폴더로 | 성공 |
| `--no-progress` | 앱 여전히 실패 |

앱이 yt-dlp 출력에서 마지막 ERROR 한 줄만 남기고 버려서 더 좁힐 수 없었다. **yt-dlp 자리에 로그 래퍼(Dart로 컴파일한 exe)를 끼워** 실제 인자·작업 디렉터리·환경·전체 stdout/stderr를 받았다.

경로 바이트는 정상이었다(`eb ac b8 ec 84 9c` = `문서`의 올바른 UTF-8). 경로가 잘못된 적은 없다.

### 진짜 원인

`lib/services/process/process_runner.dart`의 `start()`가 **엄격한 `utf8.decoder`** 를 쓰고 있었다.

yt-dlp(파이썬)는 stdout이 파이프일 때 로케일 코드페이지로 인코딩한다. 이 PC는 cp949라, 내려받기 중

```
[download] Destination: C:\...\OneDrive\문서\data\tmp\...\audio.webm
```

이 줄이 cp949 바이트로 나온다. 엄격한 UTF-8 디코더가 `FormatException`을 던지고, `catchError`가 그걸 삼키면서 `forEach`가 끝난다. **그 순간부터 파이프를 아무도 비우지 않는다.** 버퍼가 차면 yt-dlp가 stdout 쓰기에서 막히다 `OSError`로 죽고, 그 메시지가 `[Errno 22]`다.

메타데이터 조회만 멀쩡했던 것도 같은 이유로 설명된다 — `fetchMetadata`는 `Process.run`을 쓰는데 그 기본 인코딩이 `systemEncoding`이라 cp949를 제대로 읽었고, `--dump-single-json` 출력은 `\uXXXX` 이스케이프라 어차피 순수 ASCII였다.

### 수정

`Utf8Decoder(allowMalformed: true)`. 파싱에 쓰는 값(진행률·`ERROR:` 접두사)은 전부 ASCII라 깨진 바이트를 대체 문자로 흘려보내도 동작에 영향이 없다. **핵심은 던지지 않는 것.**

회귀 테스트 5건. 그중 하나는 같은 입력을 엄격한 디코더에 넣어 실제로 던지는지 확인한다 — 이게 없으면 나머지 테스트가 아무것도 증명하지 않는다. 또 하나는 "한 줄이 깨진다"가 아니라 "그 뒤로 스트림이 죽는다"가 진짜 증상이라, 깨진 줄 다음 줄들이 계속 읽히는지를 본다.

### 곁가지

yt-dlp가 YouTube 추출에 JS 런타임을 요구하는데 기본 활성은 deno뿐이고 이 PC엔 없어서 제한된 클라이언트(android vr)로 우회 중이었다. 이미 있는 Node v24를 전역 설정(`%APPDATA%\yt-dlp\config`)에 물렸다. **이건 이 PC 환경 설정이라 리포에 없다.**

## 4. CI 대응

`analyze` 검사가 떨어졌다. CI는 `channel: stable`이라 지금 Flutter 3.44.8을 받는데 이 저장소의 로컬 SDK는 3.38.5(2025-12)다. 그 사이 두 API가 deprecated 됐고 `flutter analyze`는 info 수준이어도 exit 1이다.

- `SizeTransition.axisAlignment` → `alignment`
- `ReorderableListView.onReorder` → `onReorderItem`

새 인자로 바로 못 바꾼다 — 로컬 3.38에는 아직 없어서 바꾸면 로컬 analyze·test·build가 전부 깨지고 변경을 검증할 방법이 없어진다. 호출부마다 `// ignore:`를 달고 **SDK를 올릴 때 무엇을 어떻게 바꿔야 하는지**를 주석에 남겼다(`onReorderItem`은 newIndex 보정 방식이 달라 큐 재정렬을 손으로 확인해야 한다는 것도).

### 실제 앱으로 확인한 것

- 드로어 기본 닫힘 + EQ 표시 — 메인 창·전체화면 양쪽 화면 캡처
- 휠 모드 분리 — 실제 Windows 입력 주입으로 측정. 평휠 = 줄만(97370→111370ms), Ctrl+휠 = 글자만(위치 불변), Alt+휠 = 조성만(A♭→A, 위치 불변)

## 남은 것

- **CI `build-windows` 실패는 이 변경과 무관하다.** `audioplayers_windows` 플러그인이 `<experimental/coroutine>`을 쓰는데 CI 러너의 MSVC 14.51(VS18)이 이를 거부한다(STL1011). 이 브랜치에서 바뀐 빌드 관련 파일은 pubspec의 버전 한 줄뿐이라 master에서도 동일하게 실패한다. audioplayers 업그레이드는 이 앱의 피치·템포 구조 전체가 그 제약 위에 서 있어서 별도 검토가 필요하다.
- **전체화면 드로어 수정에 위젯 테스트가 없다.** `PrompterScreen` 생성에 `PlaybackController`(필수 의존성 9개)가 필요해 이번엔 넣지 못했다. 페이크를 하나 만들어 두면 이후 무대 회귀 테스트가 전부 쉬워진다.
- **로컬 Flutter SDK가 8개월 뒤처져 있다**(3.38.5 vs stable 3.44.8). 올리면 위 deprecation 두 건을 제대로 고칠 수 있지만, 553건 재검증과 재빌드를 동반한다.
- 「넌 언제나」의 `.lrc` 재타이밍.
