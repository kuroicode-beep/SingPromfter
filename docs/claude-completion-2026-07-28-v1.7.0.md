## 구현 내용

### 녹음 — 계획을 바꾼 부분 (중요)

원래 계획은 `record` 패키지였는데 **빌드가 막혔습니다.** `record_windows`가 CMake 3.23+를 요구하는데, 이 PC에는 Visual Studio 2019만 있어 번들 CMake가 그보다 낮습니다. Flutter는 PATH의 CMake가 아니라 **Visual Studio 번들 CMake**를 쓰기 때문에, CMake만 따로 깔아도 해결되지 않습니다. 해결하려면 Visual Studio 2022 설치가 필요한데, 잘 돌아가는 툴체인을 통째로 바꾸는 건 위험이 커서 다른 길을 택했습니다.

**대신 이미 갖춰 둔 ffmpeg + ProcessRunner를 재사용**했습니다 (v1.4에서 만든 것). 결과적으로 잃은 기능이 없습니다.

- ffmpeg DirectShow(`-f dshow`)로 캡처, WAV 48kHz 모노
- **라이브 입력 레벨도 그대로 됩니다**: `astats` + `ametadata`로 RMS를 표준출력에 흘리면서 동시에 파일을 씁니다. 실제로 검증했습니다
- 입력 장치 목록은 `-list_devices` 출력을 파싱 — 이 PC에서 RØDE NT-USB Mini, BEHRINGER FLOW 8 등이 정상 인식됩니다
- 정지는 stdin에 `q`를 보내 **우아하게 종료**합니다(WAV 헤더 크기가 제대로 기록됨). 3초 내 응답이 없으면 강제 종료로 넘어갑니다

### 가장 중요한 안전장치: 녹음 중 자동 진행 차단

아웃트로를 부르는 중에 다음 곡으로 넘어가 버리는 게 최악이라, **녹음 중에는 예약 큐 자동 진행을 막습니다.** `shouldAutoAdvance`를 순수 함수로 분리해 테스트로 고정했고, `PlaybackController.onSongCompleted` 진입부에서 가드합니다.

### 접근성
입력 레벨을 막대만으로 보여주면 저시력 사용자가 판단할 수 없어, **텍스트 상태를 함께** 냅니다 — `소리 없음 / 너무 작음 / 입력 좋음 / 너무 큼`. 녹음 중 표시도 색이 아니라 `● 녹음 중` 글자 + 경과 시간(모노)입니다.

### 녹음 보관함
- 새 탭 **녹음**. 테이크별 코멘트·별점(0~5)·보관 표시·듣기·삭제
- 검색은 곡 제목과 코멘트 모두, **초성 검색** 지원 (v1.3에서 뺀 `KoreanText` 재사용)
- 저장은 `recordings.json`(봉투 형식) + `data/recordings/`
  - `songs.json`과 분리한 이유: 테이크는 곡당 여러 개 쌓이고, **곡을 지워도 기록은 남아야** 합니다. `songId`는 소프트 FK이고 표시에는 `songTitle` 스냅샷을 씁니다
- 파일명은 **id 기준** — 곡 제목을 바꿔도 녹음이 끊기지 않습니다
- 3초 미만 녹음은 실수로 본 것으로 보고 파일까지 지웁니다

## 소장님 확인이 필요한 부분

실제 마이크 녹음은 직접 해보셔야 합니다.
1. 곡 선택 → 재생 바의 **마이크 버튼**으로 녹음 시작
2. `● 녹음 중` 표시와 경과 시간, 입력 상태 문구가 뜨는지
3. **헤드폰 사용을 권장합니다** — 스피커로 들으면 반주가 마이크로 섞여 들어갑니다
4. 정지 후 **녹음 탭**에서 들어보기 · 코멘트 · 별점
5. 녹음 중에는 다음 곡으로 자동으로 넘어가지 않는지
