## 구현 내용

### 외부 도구 계층 (`lib/services/process/`)
- `ProcessRunner` — `Process.start` 기반. 작업이 수십 초~수 분이고 진행률을 스트림으로 흘리며 취소가 필요해 `Process.run`을 쓰지 않는다. **추상 클래스로 둬서 테스트는 가짜 구현을 주입**하므로 모킹 패키지가 필요 없다.
- `ExternalToolLocator` — 사용자 지정 경로 → PATH → 알려진 설치 위치 순으로 탐색. 순위 결정은 순수 함수라 파일시스템 없이 테스트한다. 못 찾으면 설치 명령 안내 + 직접 경로 지정.
- 진행률 파서 — 전부 순수 함수.
  - yt-dlp: `[download] 42.3% of ...` 형태에서 비율 추출
  - ffmpeg: `-progress pipe:1 -nostats`의 key=value. **`out_time_ms`가 이름과 달리 마이크로초**라는 점을 실측으로 확인해 반영했다(2초 입력에서 `out_time_us`/`out_time_ms` 모두 2000000).

### 가져오기 (`youtube_import_service.dart`)
1. `--dump-single-json`으로 **내려받기 전에** 제목·가수·길이를 조회 → 미리 확인하고 취소할 수 있다
2. `-x --audio-format mp3`로 오디오 추출
3. 작업은 `data/tmp/<jobId>/`에서 진행하고 **성공했을 때만** 라이브러리로 옮긴다 — 반쯤 받아진 파일이 목록에 노출되지 않는다
4. 30분 초과 영상은 거른다(라이브 등)
5. URL 검증은 호스트 화이트리스트 — `youtube.com.evil.test` 같은 사칭 주소를 막는다

### 반주 처리 방식 (`MrSourceMode`)
- **MR 영상 그대로**(기본, 음질 최상·처리 없음) / **원곡 그대로** / **보컬 줄이기**(ffmpeg 센터채널 제거, 실험적·음질 저하 명시)
- AI 보컬 분리는 로드맵대로 v2.0.0에서 SVIL 서비스로

### 작업 큐 (`ImportJobController`)
동시 실행 1건(데스크톱에서 ffmpeg 병렬은 자원만 뺏김), 취소 시 프로세스 kill + 임시 폴더 정리. 큐 로직은 순수 함수로 분리해 테스트한다.

### 화면 (`youtube_import_panel.dart`)
새 목적지 `AppDestination.jobs`(가져오기). 링크 입력 · 반주 방식 선택 · 작업 진행률 목록.

**저작권 문구 상시 노출** (소장님 확정 방침):
- "개인이 저작권을 소유한 링크만 사용해야 합니다."
- "개인적 용도의 사용에 대한 책임은 사용자 본인에게 있습니다."

기능을 한 화면 + 한 진입점으로 격리해, 공개 배포 시 제외해야 하면 탭만 빼면 되도록 했다. 다운로드 음원의 공유·업로드 경로는 만들지 않았다.

### 부수 개선
`AppDestination`에 라벨·아이콘을 부여해 상단 탭이 **하드코딩 대신 순회**로 만들어진다. 앞으로 화면이 늘어도 탭 코드는 그대로다.
