# 완료 보고서 — v1.5.0 가사 가져오기 · 싱크 표시

작성일: 2026-07-28
작성자: Claude Code
기준: v1.4.0(`2dade3c`) → `1.5.0+1`

## 구현 내용

### LRC 파서 (`models/timed_lyrics.dart`)
- `[mm:ss.xx]` / `[mm:ss.xxx]` / `[mm:ss]` / `[mm:ss:xx]` 형식
- **한 줄에 여러 타임스탬프**(후렴 반복) → 각각의 줄로 전개
- `[ti:]`/`[ar:]`/`[offset:]` 메타 태그, BOM·CRLF 허용
- 줄 찾기는 **이진 탐색**

**설계 판단**: LRC가 자기 줄 목록을 직접 들고 있게 했다. `LyricsLineUtils.splitLines`는 빈 줄을 버리므로 그 인덱스에 타임스탬프를 얹으면 어긋난다. 둘을 섞지 않아 인덱스 불일치 가능성을 원천 차단했다.

### 가사 가져오기 (`lrclib_client.dart`, `lyrics_sync_service.dart`)
- LRCLIB(lrclib.net, API 키 불필요). 제목·가수·길이로 **정확 조회 → 실패 시 검색 폴백**
- 검색 결과는 **길이가 가장 가까운 싱크 가사**를 고른다
- 네트워크 실패·깨진 JSON·404 모두 조용히 null로 떨어져 앱이 죽지 않는다
- `package:http`의 `Client` 인터페이스를 써서 테스트는 가짜 클라이언트를 주입한다

### 저장 (`repository/lrc_store.dart`)
`data/lrc/<songId>.lrc` 사이드카.

**파일명을 제목이 아니라 id 기준으로 둔 이유**: 제목을 바꿀 때 `updateSong`이 파일명을 줄줄이 바꾸는 캐스케이드가 있는데, LRC는 앱이 관리하는 파일이라 거기 얽히지 않는 편이 안전하다. (사용자가 직접 여는 가사 txt는 기존대로 제목 기준 유지)

### 싱크 표시 모드
- `PrompterDisplayMode.timed` 추가. 3줄 창 레이아웃 재사용
- 계산식: `노래 시각 = 재생 위치 − 트림 시작 + 가사 오프셋`
- 싱크 가사가 없으면 자동으로 기존 추정 방식으로 되돌아간다

### 가사 선행 시점 조절 (소장님 요청 "싱크 낮춰서")
- `BackingTrack.lyricsOffsetMs` — 곡·슬롯별로 저장
- **−3초 ~ +3초**, 0.2초 단위. 슬라이더 대신 **큰 −/+ 버튼**(50dp) + 모노 숫자
- 표기를 값이 아니라 의미로: `0.6초 먼저` / `동시` / `0.4초 늦게`

### 백업 반영
`lrc/` 디렉터리를 내보내기·가져오기에 포함. 백업은 모델을 훑는 구조라 `Song.lrcFileName`을 추가하지 않으면 조용히 빠진다는 점을 반영했다.

## 소장님 확인이 필요한 부분

1. 곡 선택 → 표시 설정 펼치기 → **가사 가져오기** → 싱크 가사를 찾는지
2. 표시 모드를 **싱크 가사**로 두고 재생 → 줄이 실제 타이밍에 맞게 넘어가는지
3. **가사 표시 시점** −/+ 로 선행/지연이 체감되는지
4. 한국 가요는 LRCLIB에 없을 수 있어요. 그때는 "찾지 못했습니다" 안내가 뜨고 기존 모드로 계속 쓸 수 있습니다.
